# Weather Digest CLI

Консольная утилита «Погодный дайджест». Принимает один или несколько городов,
получает по ним прогноз погоды через открытый API Open-Meteo, выводит результат
в терминал в виде таблицы и сохраняет отчёт в JSON-файл.

## Требования к окружению

- Node.js версии 20 и выше (используется встроенный `fetch`)
- npm

## Установка

```bash
git clone https://github.com/StarostinLF/weather-digest-cli.git
cd weather-digest-cli
npm install
cp .env.example .env
```

## Переменные окружения

Файл `.env` создаётся на основе `.env.example`. Все переменные необязательны —
без них используются значения по умолчанию.

| Переменная           | Назначение                                             | По умолчанию                                     |
| -------------------- | ------------------------------------------------------ | ------------------------------------------------ |
| `GEOCODING_API_URL`  | URL запроса геокодинга                                 | `https://geocoding-api.open-meteo.com/v1/search` |
| `WEATHER_API_URL`    | URL запроса прогноза погоды                            | `https://api.open-meteo.com/v1/forecast`         |
| `REQUEST_TIMEOUT_MS` | Таймаут запроса к API, мс                              | `5000`                                           |
| `REPORTS_DIR`        | Каталог для сохранения отчётов                         | `reports`                                        |
| `TEMPERATURE_UNIT`   | Единица измерения температуры (`celsius`/`fahrenheit`) | `celsius`                                        |

## Запуск

```bash
node src/index.js --city "Нижний Новгород" --days 3
```

### Параметры

| Параметр     | Обязателен | Описание                                                                 |
| ------------ | ---------- | ------------------------------------------------------------------------ |
| `--city`     | да         | Название города. Несколько городов через запятую: `--city "Москва,Сочи"` |
| `--days`     | нет        | Количество дней прогноза, число от 1 до 7. По умолчанию — 3              |
| `--no-cache` | нет        | Игнорировать сохранённый на сегодня отчёт и запросить данные заново      |

Примеры:

```bash
node src/index.js --city "Москва"
node src/index.js --city "Москва, Сочи, Казань" --days 7
node src/index.js --city "Москва" --no-cache
```

## Пример вывода

```
Москва, Россия
Координаты: 55.75204, 37.61781
┌─────────┬──────────────┬─────────┬──────────┬────────────┐
│ (index) │ Дата         │ Мин, °C │ Макс, °C │ Осадки, мм │
├─────────┼──────────────┼─────────┼──────────┼────────────┤
│ 0       │ '2026-09-13' │ 7.7     │ 16.2     │ 0          │
│ 1       │ '2026-09-14' │ 9.2     │ 18.4     │ 0          │
│ 2       │ '2026-09-15' │ 11.7    │ 18.6     │ 0.1        │
└─────────┴──────────────┴─────────┴──────────┴────────────┘
```

Отчёт по каждому городу дополнительно сохраняется в файл вида
`reports/москва-2026-09-13.json`. Если за сегодня отчёт уже есть, повторный
запуск возьмёт данные из этого файла без обращения к сети (кроме запуска
с флагом `--no-cache`).

## Обработка ошибок

Города обрабатываются параллельно и независимо: ошибка по одному городу
выводится в консоль, но не прерывает обработку остальных.

| Ситуация                                      | Реакция утилиты                                           |
| --------------------------------------------- | --------------------------------------------------------- |
| Не передан `--city` / некорректный `--days`   | Сообщение об ошибке аргументов, выход до сетевых запросов |
| Город не найден (пустой результат геокодинга) | Сообщение «Город … не найден» для этого города            |
| Ответ API со статусом 4xx                     | Сообщение о некорректном запросе с кодом статуса          |
| Ответ API со статусом 5xx                     | Сообщение о недоступности сервера с кодом статуса         |
| Нет сети / сервер недоступен                  | Сообщение о сетевой ошибке                                |
| Превышен таймаут запроса                      | Сообщение о превышении времени ожидания                   |
| Некорректный JSON в ответе                    | Сообщение об ошибке разбора ответа                        |

Все сообщения об ошибках выводятся без стек-трейса.

### Код завершения процесса

- `0` — хотя бы один город обработан успешно;
- `1` — ошибка аргументов командной строки, либо все запрошенные города завершились с ошибкой.

## Структура проекта

```
src/
  index.js              точка входа: разбор аргументов, запуск, коды завершения
  config.js             конфигурация из переменных окружения
  errors.js             классы ошибок приложения
  cli/
    parseArgs.js         разбор и валидация аргументов командной строки
  api/
    httpClient.js        обёртка над fetch: таймаут, обработка статусов и JSON
    geocodingApi.js       запрос геокодинга
    weatherApi.js         запрос прогноза погоды
  services/
    weatherDigest.js      бизнес-логика: геокодинг → прогноз → кэш, параллельно по городам
  storage/
    reportStorage.js      сохранение и чтение отчётов, проверка кэша по дате
  format/
    consoleFormat.js      вывод отчёта и ошибок в консоль
docs/
  postman/                коллекция Postman с примерами запросов и ответов
test/
  *.test.js               тесты на node:test
```

### Docker

```bash
docker build -t weather-digest-cli .
docker run --rm -v "$(pwd)/reports:/app/reports" weather-digest-cli --city "Москва" --days 3
```

Параметры (таймаут, каталог отчётов и т. д.) передаются через `-e`, например
`-e REQUEST_TIMEOUT_MS=8000`. Каталог `reports` монтируется томом, иначе отчёты
останутся только внутри контейнера и будут потеряны при его удалении.
